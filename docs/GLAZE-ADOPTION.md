# Glaze integration roadmap

**Current truth:** The UI in `apps/web/` is an accessible semantic prototype. It does not consume the approved Glaze V1.7 runtime or have product-specific acceptance evidence.

**Source of authority:** `GoreeCloud/glaze` lifecycle registry, Stable contract, tokens and acceptance records. At the latest verified check the release anchor was 1.7.0; refresh before implementation or consumer acceptance.

## Required work

1. Map Code's repository pages, issues, pull requests, review surfaces, pipelines, administration, onboarding, authentication and error/recovery states to Glaze semantic roles and the current approved runtime.
2. Integrate actual Glaze packages and tokens, not local competing design-system values; reference the exact accepted source revision.
3. Validate light/dark, increased contrast, forced colors, reduced transparency, reduced motion, keyboard and screen-reader experiences across representative breakpoints.
4. Ensure navigation and controls have appropriate targets, focus order, meaningful labels and non-color-only status information.
5. Run current Stable consumer acceptance and record real evidence linked to the exact Code candidate head.

Do not claim conformance for cosmetic branding alone. Accessibility failures block qualification.
